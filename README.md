# Telegram anti-spam bot

Антиспам-бот для группы обсуждения Telegram-канала.

Каждое сообщение участника, которому бот ещё не доверяет, проверяется так:

1. **CAS** (Combot Anti-Spam) — публичная база спамеров. Если автор в ней есть, сообщение удаляется, автор банится.
2. Модель отвечает на набор простых вопросов «да/нет» о сообщении, профиле автора и посте, под которым оно
   оставлено: предлагает ли заработок или ставки, 18+, фишинг, самопиар, зовёт ли в ЛС или канал, мог бы
   комментарий стоять под любым постом, рекламирует ли что-то профиль, по теме ли он. Отвечает **Cloudflare
   Clef-flash**; если Clef упёрся в лимит или не ответил — **TypeSafe Jev**. Модель не решает, спам ли это:
   решение принимают правила в коде.

Все вопросы, пороги и правила лежат в [`questions.py`](questions.py). Ответ ≥ 0.7 считается «да», < 0.3 — «нет»,
между ними — «не уверен».

| Признаки | Действие |
|---|---|
| фишинг, или заработок/ставки/18+ и зовёт в ЛС/канал | удалить и забанить |
| заработок/ставки/18+ | удалить, админ решает о бане |
| самопиар или зовёт в ЛС/канал, и не по теме поста | удалить |
| комментарий «под любой пост» и реклама в профиле (нейрокомментинг) | удалить, админ решает о бане |
| самопиар по теме поста, или любой признак выше в зоне «не уверен» | ничего не делать, спросить админа |
| остальное | пропустить; после `TRUST_AFTER` чистых сообщений автор больше не проверяется |

Если обе модели не ответили, сообщение не трогается (ошибка в логе), а не считается чистым.

Админы получают уведомление в личку с кнопками: в боевом режиме «Разбанить» или «Забанить» / «Не спам»,
в режиме `DRY_RUN` — «Удалить», «Удалить и забанить», «Не спамер», «Ничего не делать».
Админы группы, сообщения от имени канала и автоматические репосты не проверяются.
Под каждым новым постом канала бот публикует правила из `rules.txt` первым комментарием.

В режиме `DRY_RUN=true` бот ничего не удаляет и не банит, а только присылает уведомления.

## Запуск

```bash
./set-secrets.sh                         # создаёт .env и rules.txt
mkdir -p data && chown 10001:10001 data
docker compose up -d --build
```

`set-secrets.sh` спрашивает ключи и создаёт `.env`, а `rules.txt` — из шаблона `rules.example.txt`, подставив
контакт для жалоб на ошибки бота. Вместо скрипта можно скопировать `.env.example` в `.env` (`chmod 600`) и
`rules.example.txt` в `rules.txt` вручную. `rules.txt` должен существовать до запуска: иначе Docker создаст
на его месте пустую папку.

## Настройка под свою группу

- **`rules.txt`** — текст правил, который бот публикует под каждым постом канала. Шаблон общий, поправьте
  его под свою группу: что считается спамом, куда писать при ошибке. Поддерживается HTML-разметка Telegram
  (`<b>`, `<i>`, `<a href="…">`). Файл не хранится в git, `git pull` его не перезапишет. После правки
  выполните `docker compose restart`. Чтобы не публиковать правила, задайте `POST_RULES=false`.
- **`GROUP_DESCRIPTION`** в `.env` — одна фраза о теме группы, например «Жизнь русскоязычных в Барселоне».
  Оставьте пустой, если сказать нечего: модель видит этот текст.
- **Вопросы и правила** — в `questions.py`. `TRUST_AFTER` в `.env` — сколько чистых сообщений нужно для доверия.
  Начните с `DRY_RUN=true`, посмотрите на уведомления несколько дней и только потом переключайте в боевой режим.

Бота нужно добавить админом в группу обсуждения (право удалять сообщения и банить), а каждый админ из
`ADMIN_IDS` должен один раз написать боту `/start`: иначе Telegram не даст боту прислать уведомление.

## Команды в личке бота (только для админов)

- `/check <текст>` — оценить текст: решение и ответ на каждый вопрос.
- Картинка с подписью или без — оценить картинку.
- `/stats` — действия за последние 24 часа.
- `/whoami` — свой Telegram ID.

## Самопроверка

```bash
docker compose run --rm -T antispam python bot.py --selftest "текст сообщения" [картинка.png [ШxВ]]
```

Оценивает текст как обычно, а затем имитирует исчерпанную квоту Clef, чтобы проверить переход на Jev.

## Проверка вопросов на примерах

После правки `questions.py` прогоните 30 выдуманных комментариев из [`eval/cases.py`](eval/cases.py) с
ожидаемым решением для каждого:

```bash
docker compose up -d --build   # правки в questions.py должны попасть в образ
docker compose run --rm -T -v ./eval:/eval -w /eval -e PYTHONPATH=/app antispam python run_eval.py both
```

`jev`, `clef` или `both` — какие модели спрашивать. Один прогон Jev — около 40 тыс. токенов (доли цента),
прогон Clef тратит его дневную бесплатную квоту. Скрипт печатает по строке на пример: ожидаемое и
полученное решение и ответы ≥ 0.3. Ошибся бот на настоящем сообщении — добавьте похожий пример в
`cases.py` (без имени и профиля настоящего автора).
